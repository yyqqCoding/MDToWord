# 反馈入口限流

## 1. 为什么限流

反馈入口无需登录，任何人都可以提交 Markdown。限流保护 Render、Supabase 和 Agent 模型
预算；它不是身份认证，也不能依赖浏览器标识、User-Agent 或 Referer 作为可信身份。

## 2. 当前窗口

~~~text
同一 IP：60 秒 1 次
同一 IP：1 小时 5 次
同一 IP：24 小时 10 次
所有 IP：1 小时 30 次
~~~

限流器在应用生命周期内共享，用单调时钟记录消费时间。一个 asyncio.Lock 原子保护
清理、检查和消费；锁内不访问 Supabase。超限返回 429、精确 Retry-After 和 no-store，
但不透露命中的窗口、IP 或内部限流键。

## 3. 客户端 IP

生产只使用经过边缘验证的单值 CF-Connecting-IP。缺失、非法、多值或无法证明可信时返回
503 client_ip_unavailable；不能回退到可由调用方伪造的 X-Forwarded-For，也不能把所有
请求归到 Render 代理地址。

解析器接受可路由 IPv4/IPv6，规范化 IPv4-mapped IPv6，并按 IPv6 /64 生成限流键。上线
前要用 Wi-Fi、手机流量和伪造请求头做黑盒验证；证据只保存状态码、Retry-After、时间和
不含 IP 的请求 ID。

## 4. 进程边界

当前单 Worker 的内存限流会在进程重启时清空。增加 Uvicorn Worker、实例或跨重启额度后，
必须改用 Redis 或数据库原子限流并重新评审，不能把多个独立内存窗口称为全局限制。

过期记录要定期清理，避免恶意 IP 耗尽内存；容量上限和淘汰策略由入口实现固定。

## 5. 扩展侧行为

收到 429 时扩展不自动重试，保留用户输入并显示等待提示。503 表示无法得到可信 IP，
客户端不应通过改变请求头自行绕过。

## 6. 验收

至少测试：

1. 四个窗口边界和精确 Retry-After；
2. 并发请求的原子消费；
3. IPv4、IPv4-mapped IPv6、IPv6 /64 和非法转发头；
4. 过期清理和容量上限；
5. 429 不写重复反馈且扩展保留输入；
6. Render 边缘头覆盖和伪造头不能绕过限流。
