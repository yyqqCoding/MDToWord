# 反馈入口

## 1. 作用

反馈入口把用户看到的转换问题保存为 Agent 可处理的数据。它不调用模型、不领取任务，
也不决定是否自动修复。入口只做字段校验、限流、脱敏边界和持久化。

## 2. 输入与隐私

反馈通常包含：

- Markdown 原文；
- 用户观察到的现象和期望；
- 反馈类型、页面版本和可选联系方式。

联系方式只用于必要的人工沟通，不进入模型提示词、Artifact、日志、Langfuse、PR 或
公开 Issue。公开 Trace 只展示脱敏摘要和运行统计。

## 3. 公网限流

当前入口按客户端 IP 和全局窗口限制资源消耗：

~~~text
同一 IP：60 秒 1 次、1 小时 5 次、24 小时 10 次
全部 IP：1 小时 30 次
~~~

限流在应用生命周期内共享，并以一个 asyncio.Lock 原子完成清理、检查和消费。锁内不做
Supabase 或其他网络 I/O。超过额度返回 429、Retry-After 和 no-store；响应不暴露命中
哪一个窗口或限流键。

生产只接受经过边缘验证的单一 CF-Connecting-IP。缺失、非法、多值或无法证明可信时返回
503 client_ip_unavailable，不回退到调用方可伪造的 X-Forwarded-For。增加多 Worker 或
水平扩容后，内存限流不能冒充全局限流，应改用 Redis/数据库原子方案并重新评审。

## 4. 从入口到 Agent

写入成功后反馈状态为 pending。Scheduler 通过原子 claim 领取一条反馈，生成 run_id 和
claim lease。Gate 读取最小必要字段，并将 route 写回业务状态。入口不预判“这是后端
Bug”，也不把用户文字当作系统指令。

同一反馈可能因为租约到期重新领取，但同一 run 的恢复必须使用原 run_id 和 checkpoint，
不能在入口重复创建任务。

## 5. 维护者验收

入口改动至少验证：

1. 缺失或超长字段被拒绝；
2. 限流窗口和 Retry-After 准确；
3. 并发提交不会超额消费；
4. IP 解析不接受伪造的多值转发链；
5. 响应、日志和数据库中没有泄露联系方式；
6. 429 不被扩展自动重试，用户输入仍然保留。
